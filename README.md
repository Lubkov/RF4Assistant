# RF4 Assistant v0.1 — этап 4: главная страница

Локальный Django-сайт с каталогом водоёмов. На главной выводятся **активные** водоёмы из SQLite (по уровню доступа, затем по ID). Карточки не ведут на отдельные страницы; пункт «Карты» в меню прокручивает страницу к соответствующей карточке.

## Требования

- Python 3.10+ (рекомендуется Python 3.12 или 3.13)
- Django 5.2, Pillow (см. `requirements.txt`)
- Доступ к CDN jsDelivr для Bootstrap 5.3.3: при работе без интернета Bootstrap-стили/меню не загрузятся. Локальный CSS, JS и изображения останутся доступны.

## Запуск в Windows PowerShell

```powershell
cd C:\path\to\rf4-assistant
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте http://127.0.0.1:8000/ . Django Admin: http://127.0.0.1:8000/admin/ . Администратора создают командой `manage.py createsuperuser`.

Если виртуальное окружение уже существует, **не нужно создавать его повторно**; распакуйте файлы поверх проекта, сохранив `db.sqlite3`, `.venv` и загруженные `media/`.

## Этапы

1. Проект Django: приложения `core`, `waterbodies`, `fish`, шаблоны, настройки SQLite/static/media.
2. Модели `Waterbody`, `Fish`, `WaterbodyFish`, миграции с 18 водоёмами и 251 видом рыб. Значение `9999999` у двух супертрофеев заменено на `NULL`; связи изначально пустые.
3. Django Admin: редактирование справочников, загрузка и предпросмотр изображений, встроенные связи `WaterbodyFish` с автодополнением по названию рыбы.
4. Главная: адаптивная сетка карточек, локальная SVG-заглушка, навигация «Карты», подвал, тёмная тема по умолчанию и переключение на светлую с сохранением в `localStorage`.

## Изображения

В разделе **Водоёмы** Django Admin загрузите подготовленное изображение (рекомендуем WebP, 1280×720, 16:9). Файлы сохраняются в `media/waterbodies/`, в базе хранится относительный путь. Изображение в карточке автоматически подгоняется под 16:9 через `object-fit: cover`. Если файла нет, отображается `static/images/waterbody-placeholder.svg`.

## Развёртывание

Этот проект настроен для локальной разработки. Bootstrap подключается с CDN. `SECRET_KEY` содержит только локальное демонстрационное значение, а `DEBUG=1` по умолчанию. Для публичного сайта задайте переменные окружения `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS` и настройте отдачу статических файлов и загруженных изображений отдельным сервером/хранилищем. Не публикуйте `db.sqlite3`, `.venv`, `media/` и секреты в Git.


## Этап 5 — справочник видов рыб (`/fish/`)

Добавлена общедоступная страница `/fish/`, пункт «Рыбы» в верхнем меню, поиск по названию, фильтрация по редкости и сортировка.
В таблице показаны название, вес трофея, вес редкого трофея и редкость; веса в базе хранятся в граммах и форматируются в браузере (до 1000 г — граммы, от 1000 г — килограммы).
Рисунки редкости в `static/images/rarity-{1,2,3}.svg` повторяют согласованную палитру и геометрию.
Для 251 строки используется клиентская фильтрация без дополнительных серверных запросов.
Новые миграции не нужны; существующие справочники и данные не менялись.

После обновления файлов запустите `python manage.py check`, `python manage.py test` и `python manage.py runserver`.

## Этап v0.3 — страницы водоёмов и игровые карты

- Переходы с карточек на главной странице и из меню «Карты» ведут на `/maps/<slug>/`.
- На странице показывается название водоёма. Если карта ещё не загружена — понятное сообщение.
- `WaterbodyMap` содержит одну карту на водоём (`OneToOneField`), изображение и URL источника. Файлы хранятся в `media/waterbodies/maps/` (в БД только путь).
- Карты можно добавлять в Django Admin: «Водоёмы» → водоём → блок «Игровая карта», либо «Карты водоёмов».
- Leaflet 1.9.4 с `CRS.Simple` показывает изображение без географических координат. Колёсико мыши, кнопки `+`, `−`, перетаскивание и «Сбросить масштаб».
- Для будущих меток: координаты хранятся относительно изображения: `x = пиксельX / ширина`, `y = пиксельY / высота`, где начало координат — верхний левый угол. Сейчас метки и подсказка координат не реализованы.
- Leaflet загружается с CDN jsDelivr: для просмотра карты нужно подключение к интернету.
- Добавлена миграция `waterbodies/0003_waterbodymap.py`. Выполните `manage.py migrate`. Существующие записи и загруженные изображения не меняются.

### Пример изображения

В архиве включён образец карты `sample_maps/old_burg_lake.webp` (2048×2048) из предоставленного PNG. Загружайте файл вручную через Django Admin для «оз. Старый Острог». Не перемещайте его прямо в `media/` без создания записи `WaterbodyMap`. Рекомендовано использовать WebP с исходным разрешением 1600–2048px, если оно доступно, без искусственного увеличения.


### Map viewer behavior update

- Map viewing area is up to 800 × 800 px (responsive on narrow screens).
- When the entire image fits the viewing area, dragging is disabled.
- Zooming in enables dragging only if part of the image extends outside the viewing area; zooming back out disables it again.
- The waterbody title includes the smaller access-level label (e.g. `1 ур.`).

## Этап v0.4 — управление браузерным кэшем и UUID изображений

- HTML-ответы (включая HTML-фрагменты HTMX): `Cache-Control: no-store` при `DEBUG=True`; `no-cache, must-revalidate` при `DEBUG=False` (`core/cache_middleware.py`).
- Локальные CSS, JS и SVG в шаблонах вызываются через `{% load versioned_static %}` и `{% versioned_static '...' %}`. При `DEBUG=True` к URL добавляется SHA-256 содержимого, который меняется при изменении файла. При `DEBUG=False` используются URL файлов с хэшами Django `ManifestStaticFilesStorage`.
- В production после обновления статических файлов обязательно выполняйте `python manage.py collectstatic --noinput` и настройте веб-сервер (или WhiteNoise) на обслуживание `STATIC_ROOT` /static/; Django `runserver` с `DEBUG=False` не является production-сервером статических файлов. Нельзя удалять прежние hashed-файлы, пока старые HTML-ответы ещё могут ссылаться на них.
- Новые изображения `Waterbody.image` и `WaterbodyMap.image` через Django Admin получают уникальные UUID v4 имена. Загруженный `*.webp` превращается в `waterbodies/<uuid>.webp` или `waterbodies/maps/<uuid>.webp`; другие форматы сохраняют **настоящее расширение**, преобразования формата нет.
- Старый файл удаляется при замене / удалении изображения **после commit транзакции** и только если к нему не обращаются другие записи. Внешняя ручная замена файла в `media/` с тем же именем не поддерживает версионирование; загружайте новый файл через Admin.
- Существующие записи БД и пути изображений остаются без изменений. Миграция `waterbodies/0004_uuid_image_upload_paths.py` меняет только upload_to у полей.
- При будущей настройке reverse proxy/CDN для `/media/` можно включить длительный кэш для UUID-имен, но избегайте такой политики для старых файлов с постоянными именами.

### Обновление существующего проекта

1. Сделайте резервные копии `db.sqlite3` и папки `media/` (если они содержат данные).
2. Замените исходники проекта файлами из архива, сохранив свои локальные БД, медиафайлы и `.env`.
3. В активированном виртуальном окружении выполните:

   ```bat
   .\.venv\Scripts\python.exe manage.py migrate
   .\.venv\Scripts\python.exe manage.py check
   .\.venv\Scripts\python.exe manage.py test
   ```

4. Запустите сайт как обычно; при следующей загрузке WebP через Admin имя будет новым UUID.
5. Для production с `DEBUG=False` дополнительно выполните `collectstatic` и настройте раздачу `static/` и `media/` на веб-сервере.
